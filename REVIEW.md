# REVIEW.md

Defects found in the starter `app/main.py`. All of them are fixed in the submitted version.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses `punch_in.replace(hour=..)` in whatever time zone the datetime has (naive server time), but shift times are IST. On a UTC server a 09:35 IST punch looks like 04:05. | Server in UTC: punch at 09:45 IST reports about -225 -> 0 or a huge value for evening punches. | Convert the instant to IST and build the shift start as an IST datetime (`shift_start_at`). |
| 2 | `compute_late_minutes` | Floors to whole minutes **before** comparing `> 10`, so 09:40:30 gives 10, which is not `> 10`, so 0. R2 says strictly more than 10:00 grace is late. Seconds are also not truncated. | Punch-in 09:40:01 must give late = 10, starter gives 0. | Compare **seconds** `> 600`, then floor to minutes. Instants are truncated to whole seconds on input. |
| 3 | `compute_late_minutes` | Overnight shifts ignored: the shift start is always on the punch-in's own calendar day. | Shift 22:00-06:00, punch-in 00:30 next day: start is built on the wrong day. | `attendance_date()` implements R1 (previous-day rule); lateness is measured from that day's shift start. |
| 4 | `compute_work_hours` | `round(x, 2)` is float/banker's rounding, not half-up; no seconds truncation. | 9 h 7 min 30 s = 9.125 h: starter gives 9.12, R4 wants 9.13. | `Decimal(seconds)/Decimal(3600)` quantized with `ROUND_HALF_UP`. |
| 5 | `compute_overtime` | No 30-minute minimum (any positive minute counts, R3), overnight shift end is not moved to the next day, and it mixes naive and aware datetimes (`TypeError`). It is also never called: there is no punch-out endpoint. | Punch-out 18:45 for 18:30 end returns 15, should be 0. | `compute_overtime_minutes` floors, applies the `>= 30` rule; `shift_end_at` adds a day for overnight shifts; punch-out endpoint added. |
| 6 | `punch_in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises `TypeError` -> HTTP 500. | POST punch-in with `emp_code: "NOPE"`. | Look up the employee first, 404 if missing. |
| 7 | `punch_in` | Check-then-insert race and no unique index: two parallel requests both pass the `find_one` and both insert. | Fire 10 identical requests in parallel: several 201 and duplicate rows. | Unique index on `(emp_code, date)` and `insert_one` only; `DuplicateKeyError` -> 409. |
| 8 | `punch_in` | Time handling: `datetime.fromtimestamp` / `datetime.now()` use the server's local naive time. The `date` is therefore the server's date, not the IST date (R1). Also `if body.punched_at` treats `0` as "missing". | Run on a UTC server, punch at 23:30 IST: wrong `date`. | `punched_at` -> UTC-aware datetime truncated to seconds; date from `attendance_date()`; `is not None` checks. |
| 9 | `PunchInIn` | `punched_at: Optional[int]` is lax: accepts `"123"`, `1.0`, seconds-looking values like `1783312500`, negatives and huge numbers (`OverflowError` -> 500). `status: str` accepts `ABSENT`, `LEAVE` or any text. | POST `punched_at: 1783312500` creates a record in 1970; `status: "banana"` is stored. | Strict int with range 1e11..4.1e12 (422 otherwise); `status` is `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 10 | `punch_in` response | Returns `id` (the Mongo `_id`) and raw datetimes instead of epoch milliseconds. The contract says `_id` never leaves the API. | Response contains `"id": "66f..."` and ISO strings. | `to_api_record()` builds the response: no id, instants in epoch ms, defaults for missing legacy fields. |
| 11 | `create_employee` | Same check-then-insert race as #7, no unique index on `emp_code`. | Parallel creates with the same code. | Unique index `emp_code`; `DuplicateKeyError` -> 409. |
| 12 | `EmployeeIn` / `create_employee` | No validation: emp_code format, e-mail, `HH:MM` shape, `shift_start == shift_end`, impossible `joined_on` (`2026-02-30`), field lengths. `created_at` stored as naive local time and returned as a datetime, not epoch ms. | POST `shift_start: "9:5"`, or both shifts `10:00`. | Pydantic patterns/lengths + validators (422); `created_at` is UTC `now` returned as epoch ms. |
| 13 | `list_employees` | `skip = page * page_size` skips the whole first page (should be `(page-1) * page_size`). `page=0` or negative gives a negative skip -> 500. | `GET /employees?page=1` misses the first 20 employees. | `(page - 1) * page_size`; `page >= 1` enforced (422). |
| 14 | `list_employees` | `total` counts the whole collection, ignoring the department filter (R10). No sort, so pages are unstable (contract: `emp_code` ascending). `page_size` unbounded. | Filter by department: `total` is the company size. | `count_documents(q)` with the same filter, `sort("emp_code")`, `page_size` 1..100. |
| 15 | `list_attendance` | Loads **every** matching document into Python, sorts and slices there. Very slow and memory-hungry at ~100k records. No indexes exist. | `GET /attendance` on 100k docs. | Sort/skip/limit in MongoDB with indexes `(date desc, emp_code)`, `(status, date desc, emp_code)` and `(emp_code, date)`. |
| 16 | `list_attendance` | Sorts by date only (contract: then `emp_code` ascending), so equal dates paginate unstably. | Same record can appear on two pages. | Sort `[("date", -1), ("emp_code", 1)]`. |
| 17 | `list_attendance` | No validation: `page=0` slices `[-n:0]`, unbounded `page_size`, free-text `status`, bad dates, `date_from > date_to` not rejected. Leaks `id` and raw datetimes; legacy docs without `half_day`/`history` are returned as is. | `GET /attendance?page=0`, `?date_from=2026-07-09&date_to=2026-07-01`. | Query constraints + `Literal` status + date parsing (422); `to_api_record()` normalises the output. |
| 18 | `MongoClient(...)` | Created without `tz_aware=True`, so datetimes come back naive and comparing them with aware values raises `TypeError`. No indexes are created at startup. | Any code that subtracts a stored punch time from an aware datetime. | `tz_aware=True`; `ensure_indexes()` runs in the app lifespan and is idempotent. |
| 19 | `/health` | Always returns `ok`, even when MongoDB is down. Contract: 200 only if a ping succeeds, else 503. | Stop MongoDB and call `/health`. | `client.admin.command("ping")`, 503 on failure. |
| 20 | Missing endpoints | `punch-out`, `PATCH` regularization, the four analytics endpoints and `/admin/explain` do not exist. | Contract vs. starter. | Implemented. Punch-out and PATCH are race-safe (conditional `find_one_and_update`). |

## Looked at and judged **not** a defect
- `load_dotenv()` at import time: by default it does **not** override real environment variables, which is what the contract asks for.
- `IST = timezone(timedelta(hours=5, minutes=30))`: correct, IST has no daylight saving.
- `doc.pop("_id")` after `insert_one`: needed, because PyMongo adds `_id` to the dict.
- New punch-in documents start with `punch_out: None`, `work_hours: None`, `overtime_minutes: 0`, `half_day: False`, `history: []`, exactly as the data model says.
- Plain synchronous `def` endpoints with PyMongo: FastAPI runs them in a thread pool, and the MongoClient is thread-safe.
- `201` on creation endpoints and the `409` for an `emp_code` that already exists are the right codes (only the race was wrong).
